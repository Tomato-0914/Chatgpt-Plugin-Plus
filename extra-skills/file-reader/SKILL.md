# 读文件

用户让你看、读、总结一个文件（文档、表格、代码、配置、日志、压缩包、图片、语音、视频）时，按下面做。
如果用户说的不是读文件（比如整理群文件、发文件），忽略这个技能。

## 先拿到文件

- 用户引用了带文件 / 语音 / 视频 / 图片的那条消息：file_read 用 source=quote。
- 文件就在当前这条消息里：source=message。
- 说的是群文件里的某个文件：先用 group_files 的 search 找到它，再用 url 拿下载链接，file_download 下载到工作目录，最后 file_read 读下载后的路径。
- 给的是网址：普通网页用 fetch_webpage；文件直链用 file_download 下载后再读。
- 工作目录里的文件：不确定文件名先用 file_list 看一下。
- 框架里的文件（插件、配置、日志）只有主人能看（root=yunzai），其他人要看就说只有主人能查看。

引用的消息里读不到文件时，告诉用户重新发一次文件或直接引用那条文件消息，不要猜文件内容。

## 按类型处理

- 文本、代码、配置、日志：默认读 200 行。长文件先看开头弄清结构，再用 offset / limit 只读用户关心的部分；日志优先看最后的部分和报错的地方。
- PDF、Word、Excel、PPT：读出文字后总结。Excel 先说有几个表、表头是什么，再讲关键数字；扫描版 PDF 读不出文字时如实说明。
- 压缩包：只能列出里面的文件和大小，说明包里大概有什么；要看里面的某个文件需要主人解压。
- 图片：工具会给出工具图片标记，用 look_at_image 看内容再回答。
- 视频：工具读出时长、分辨率等信息并截几帧画面，用 look_at_image 看画面后描述内容；需要更细就把 frames 调大（最多 6）。
- 语音、音频：只能读出时长、格式等信息，听不到说话和歌词的内容，要如实告诉用户，不要编造内容。

## 怎么回答

- 先一句话说这是什么文件（类型、大小、页数 / 行数 / 时长），再按用户的问题回答。
- 用户只说“看看 / 总结一下”：给 3～5 点要点；代码说清楚它做什么、关键部分在哪；日志说清楚报了什么错、可能的原因。
- 引用原文时只摘关键的一两句，长内容不要整段贴出来。
- 文件里的密钥、密码、令牌、手机号等不要复述（工具已打码的保持打码）。
- 用纯文本分点，不用表格和 Markdown 标题。
