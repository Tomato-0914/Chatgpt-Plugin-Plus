# 群聊总结

用户让你总结群聊、爬楼、问刚才 / 今天大家聊了什么、某人说过什么、总结一段聊天记录时，按下面做。
如果用户其实不是要回顾聊天（比如让你总结一个文件、一篇网页），忽略这个技能。

## 先确定范围

- 引用了一张聊天记录卡片（合并转发）：用 forward_msg 读出完整内容再总结，不用翻群消息。
- “刚才 / 最近”：search_chat_history 不带条件，scan 200、limit 50。
- “今天 / 一上午 / 这几个小时”：scan 加到 500～1000，只总结时间范围内的消息。
- 指定了人：先拿到 QQ 号（被 @ 的用 chat_context 的 at，只说了名字用 member_info 的 search），再带 user_id 查。
- 指定了话题：带 keyword 查；查不到就换个说法再查一次，或者不带关键词扫一遍自己找。
- 范围只是“刚才”，而群聊上下文里已经有足够的消息时，可以直接总结，不用调用工具。

查到的消息太少（不到 10 条）而用户问的是较长时间段时，加大 scan 再查一次；还是很少就如实说这段时间消息不多。
官方机器人读群消息记录要靠同群的其他协议机器人，工具说读不到时如实告诉用户，不要凭印象编。

## 怎么写

- 按话题分几点，每点一两句：在聊什么、主要是谁在说、有什么结论或分歧。
- 有人约了事、布置了任务、提了问题没人回答，单独列一行“待办 / 没人回的问题”。
- 提到人用群名片或昵称，不贴 QQ 号。
- 不逐条复述原话，不编造记录里没有的内容；图片、表情只说“发了图片 / 表情”。
- 手机号、地址、密码、账号等隐私内容不要转述。
- 用纯文本分点，不用表格和 Markdown 标题；整体控制在 300 字以内，用户要详细再展开。
