# 扩展工具

这里的每个 `.js` 文件是一个 chaite 工具（继承 `CustomTool`）。插件启动时会自动把它们登记进工具库，
写入 `utils/tools/`，并放进工具组「扩展工具」；代码没有变化时不会重复写入。
也可以由主人发送 `#chatgpt同步工具` 手动同步。

## 启用

在管理面板（`#chatgpt管理面板`）的预设里，把工具组「扩展工具」勾选上即可。

## 修改与新增

- 修改工具请直接改这里的文件，然后重启或发送 `#chatgpt同步工具`。在面板里改的代码会在下次同步时被覆盖。
- 新增工具：复制一个现有文件改写，`name = '工具名'` 与 `function.name` 保持一致，`run(args, context)` 返回字符串。
  `context.getEvent()` 可以拿到当前消息的 Yunzai 事件 `e`。
- 删除工具：删掉这里的文件后，还需要在面板里删除对应工具（同步只会新增和更新）。
- 以 `_` 开头的文件是工具共用的辅助模块（如 `_workspace.js`），不会登记为工具。
- 新增或替换工具时，同步更新仓库自述文件末尾的「工具对照表」：新写的工具在「是否实现」一栏标 🆕，
  主人测试通过后把 🆕 改成 ✅。

## 文件工具的范围

文件工具有两个根目录（参数 `root`），路径一律相对根目录，`..`、软链接跳出去都会被拒绝：

| | 群友 | 主人 |
| --- | --- | --- |
| `workspace`（默认）：`plugins/chatgpt-plugin/data/files/` | 查看、写入、发送 | 同左 |
| `yunzai`：整个 Yunzai 框架目录 | 不能访问 | 查看（密钥打码）、修改（自动备份）、仅私聊发送 |

框架目录的规则：

- 查看的内容经 `_redact.js` 打码，密钥、令牌、密码显示为 `***`，不会出现在 AI 面前
- 不能写入带 `***` 的内容；含密钥的文件不能整体覆盖，只能用 `file_edit` 修改不含密钥的部分，避免真实密钥被覆盖
- 修改、覆盖前自动备份到 `plugins/chatgpt-plugin/data/backups/`，用 `file_restore` 查看备份和还原（还原前的内容也会备份）
- 框架里的文件只能在私聊里发送，不会把配置原文发到群里
- `.git`、`node_modules` 谁都不能访问

单个文件查看上限 200KB、写入上限 1MB、下载上限 50MB。

## 发送卡片、文件

工具照常用 `e.reply` 发送。官方机器人发不了的内容（音乐卡片，以及发送失败的文件）由 QQBot-Plugin 交给同群的野生号发送；
野生号也发不出来时，`send_music` 会让 AI 改为告诉用户歌曲链接。

## 提醒

提醒保存在 `plugins/chatgpt-plugin/data/reminders.json`，每 20 秒检查一次，到点后用设置提醒时的机器人在原来的群（或私聊）发消息并 @ 设置的人；
官方机器人的主动消息发不出时由 QQBot-Plugin 交给野生号。普通用户最多同时 5 个提醒，只能取消自己的；主人不限。

## 风险工具（群管、shell、账号设置等）

**权限设计原则（新写的工具都按这个来）**

- 主人（`other.yaml` 的 `master` 里当前机器人名下的账号）拥有全部权限，在任何群都可以直接执行
- 群管级（影响群里其他人或全群的操作）：只有主人、本群群主、本群管理员能直接执行；
  普通群友要求时不执行，发申请，由主人、本群群主、本群管理员中任意一个确认后才执行
- 主人级（shell、机器人账号、框架文件、替别人或往别的群发消息等）：只有主人能执行；其他人（包括群主、管理员）要求时发申请，只有主人能确认
- 只读的群管信息（入群申请列表、群黑名单等）只给主人、本群群主、管理员看；没有权限时绝不放宽给所有人

风险操作分两级，有权限的人要求时直接执行；其他人要求时不执行，机器人在群里 @ 第一个主人发一条申请（私聊发起时私信第一个主人）：

| 级别 | 谁能直接执行、谁能批准 | 包括 |
| --- | --- | --- |
| 主人级 | 主人 | `shell`、`bot_account`、`send_message` 给别人 / 别的群发、框架文件 |
| 群管级 | 主人，或本群的群主、管理员 | `group_admin`（禁言、踢人、拉黑、全员禁言、名片、头衔、撤回）、`join_request`、`essence` 的设置 / 取消、`group_files` 的改动、`lucky_word` 的开关 |

主人按云崽的规则判定：`other.yaml` 的 `master` 里当前机器人名下的账号（即 `e.isMaster`），`masterQQ` 不参与判定。私聊里发起的群管级操作按主人级处理。

- 回复 `#确认`、`yes`、`Y` 执行，`#拒绝`、`no`、`N` 作废（不区分大小写）
- 处理哪一条：点按钮就是按钮所在的那条；引用某条申请回复就是被引用的那条；不引用时只有一条待处理才处理它，有多条时提示引用或点按钮
- 申请一直有效，直到有权限的人处理；没有权限的人点按钮、说 Y / N 都无效（消息照常交给其他插件，不会回复“暂无权限”，申请照旧有效）；
  处理过的申请再点、再引用只会提示“已经处理过了”，不会重复执行。申请存在内存里，机器人重启后失效
- 官方机器人的申请消息是 Markdown（野生号发按钮会报错，发普通文字）。群管级的申请带「✅ 确认」「❌ 拒绝」按钮，
  用 QQ 自带的「仅管理者」权限，由 QQ 判定群主、管理员（不需要他们绑定 QQ 号），绝不会放给所有人；按钮点击是 QQ 按权限放行后才发来的，直接认可，
  手打的「#确认 编号」照常检查身份。按钮点后都显示「已处理」，结果看回复。
  主人级的申请不带按钮（指定用户的名单要换成群里的 openid，实测换出来无效、谁都点不了），主人引用申请回复；不是本群群管的主人也引用回复
- 执行的内容在申请时就已经确定，确认时不能被换成别的

- 禁言、解禁、踢人优先用官方机器人（需要是群管理员；踢人接口需要向开放平台申请），官方机器人不是管理员或失败时交给同群野生号，
  两个都失败时说明各自的原因；改名片、头衔、全员禁言官方机器人没有接口，需要同群野生号是管理员，头衔需要群主
- 群黑名单（查看、拉黑、移出）只有官方机器人有接口；野生号可以在踢人时拉黑（`kick` + `reject_add`）。查看黑名单只有主人和本群群主、管理员可以
- 撤回群友的消息交给同群野生号：引用一条消息说“撤回这条”，或按发送者（`user_id`）/ 关键词撤回最近几条；
  工具先翻野生号的群消息记录定位消息，申请确认时会列出要撤回的每一条。没有野生号的群无法撤回别人的消息
- 官方机器人撤回自己发的消息走官方撤回接口：在官方机器人的会话里引用它发的消息，或 `user_id` 填 `bot`，
  消息从 QQBot-Plugin 的本地消息记录里找（需要更新到带 `getRecentMsgs` 的 QQBot-Plugin），官方接口可能限制只能撤回较新的消息
- 接口返回的失败（如 `ERR_NOT_GROUP_ADMIN`、官方机器人撤回他人消息返回 false）会如实说明原因，不会报“完成"
- `join_request`：查看只有主人和本群群主、管理员可以；同意 / 拒绝为群管级。官方机器人（需要是管理员）优先，不行再用同群野生号
  （OneBot 的 `get_group_system_msg` / `set_group_add_request`，ICQQ 的 `getSystemMsg`）；OneBot 拒绝时不能拉黑。
  收到申请时的自动提醒由 Cheshire-Plugin 负责
- 不能对机器人自己操作；非主人不能对主人禁言、踢人、拉黑、改名片 / 头衔；管理员不能对群主、其他管理员做这些（群主可以对管理员做），对自己操作不受限制
- shell 在 Yunzai 根目录执行，输出里的密钥、令牌、密码会打码（`_redact.js`），超过 3000 字截断

## 聊天上下文

`chat_context` 让 AI 了解当前聊天：

- 对话时插件只把被引用消息里的图片带给 AI，不带文字；用户引用了一条消息时，AI 可以用 `reply` 读取它的发送人、时间、内容，以及它又引用的消息（最多 5 层）。
  官方机器人没收到被引用的消息时（没 @ 机器人的消息收不到），到同群野生号的消息记录里找；合并转发会提示用 `forward_msg` 读取
- 消息里的 @ 带给 AI 的只有名字，`at` 列出被 @ 的人的 QQ 号、群名片和身份，踢人、禁言等需要 QQ 号时用
- `clear` 等同 `#结束对话`：工具在本轮对话中途执行，本轮结束保存时会再换一次新对话，不会被旧的对话编号覆盖；只有主人能结束别人的对话

## 群信息

`group_info`、`group_members`、`group_activity`、`lucky_word` 查的都是群里的信息：

- 群友只能查当前群；主人可以用 `group_id` 指定机器人加入的其他群，群列表（`group_info` 的 list）也只有主人能看
- 群资料、成员名单：官方机器人拉不全群成员，由 QQBot-Plugin 的野生号代办（同群需要有野生号，群需要已群绑定）
- 群公告、群星级、龙王 / 群荣誉、打卡、发言榜、群数据、幸运字符只能用 QQ 账号的网页登录凭据查询（`_qqweb.js`），
  一律交给同群的野生号：ICQQ 自带凭据，OneBotv11 通过协议端的 `get_cookies` 获取；拿不到凭据或凭据失效时如实说明
- 幸运字符是机器人（野生号）自己账号的；开关本群幸运字符会影响全群，属于群管级（主人、群主、管理员直接执行，其他人要他们确认），且野生号需要是管理员

## 发消息

`send_message` 替用户发消息：

- 转告主人（to_master）：私聊发给第一个主人（`all_masters` 为所有主人），消息前注明是哪个群的谁让转告的；群友每分钟最多一次
- 私聊（private）：发给自己直接发；群友让机器人私聊别人，需要主人确认（同风险工具），发出的消息注明是谁让转告的
- 发群消息（group）：发到当前群直接发；发到别的群，群友发起时需要主人确认
- 随机 @（random_at）：在当前群随机 @ 1-5 个人（不 @ 机器人，可排除管理员、自己）
- 私聊依次尝试：与对方是好友的野生号 → 当前机器人（官方机器人发不出时由 QQBot-Plugin 交给野生号）→ 同群野生号的临时会话；
  发到别的群依次尝试当前机器人、同群野生号

## 野生号代办

官方机器人做不了的（读群消息记录、合并转发、精华、群文件、表情回应、资料卡、账号设置），交给与官方机器人在同一个框架里的野生号执行，
结果仍由官方机器人回复。官方机器人收到的消息 ID 野生号用不了，工具会按时间、内容在野生号的群消息记录里找到同一条消息（`_chat.js` 的
`quotedMessage` / `currentMessage` / `recentMessages`，撤回、精华、表情回应、合并转发共用）。没有野生号的群会直接说明做不了。

- `bot_account`：野生号退群、删好友、换头像、改昵称、改签名、改自己的群名片，全部需要主人确认（主人自己用不受限制）
- `essence`：设置 / 取消精华需要野生号是管理员；主人、群主、管理员直接执行，其他人需要他们确认。
  取消时一律到精华列表里核对是哪一条（引用的消息按消息 ID → 序号 → 同一个人、时间最接近对上），用列表给的 ID 取消；
  协议端取消失败而列表里还有时，改用 QQ 网页版按消息序号取消
- `group_files`：查看、搜索、下载链接、用量谁都能用；上传谁都能用，但野生号是管理员时普通群友上传要确认（避免绕过“仅管理员可上传”）；
  删除、改名、移动、文件夹操作由主人、群主、管理员直接执行，其他人需要他们确认。QQ 群文件只有一层文件夹。没有野生号时官方机器人只能把文件发到群文件根目录
- `emoji_reaction`：给当前消息、引用的消息或某人最近一条消息贴表情（由野生号贴）
- `forward_msg`：读引用的（或最近一条）合并转发，嵌套的展开 3 层
- 官方机器人 @ 没有绑定 QQ 号的人会被丢掉，`at_user`、随机 @ 改为写“@名字”（`_chat.mention`）
